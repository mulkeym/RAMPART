Two approaches to the redesign

Both deliver the same features — they differ in how the code is organized

A

In-Place Upgrade (Recommended)

Rewrite the CSS and HTML within the existing ui.py structure. Replace the _page() function's style block, update HTML patterns in each helper function, and add a small inline <script> block for confirms/validation.

Pros
  • No new files or architecture changes
  • Single-file deployment stays intact
  • Every page updates at once
  • Minimal risk — same routing, same forms
Cons
  • ui.py grows larger (~1200 lines)
  • CSS/JS still embedded in Python strings
B

Extract Static Assets

Move CSS into a static/style.css file and JS into static/app.js. Serve via FastAPI's StaticFiles mount. HTML templates stay in ui.py but reference external assets.

Pros
  • Clean separation of concerns
  • CSS/JS get proper syntax highlighting
  • Browser can cache static assets
  • Easier to iterate on styles independently
Cons
  • Adds StaticFiles mount to FastAPI app
  • New directory and files to manage
  • Slightly more complex deployment
